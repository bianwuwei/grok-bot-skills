# 会议记录整理成纪要或行动卡

1. 用 Read 读原始记录，只读不改原文件。
2. 先弄清受众和用途：给谁看、谁转发、要什么格式（聊天里的纪要，还是某个文件名的 .md 表格）。用户给了派活单就严格按派活单的约束和验收标准做。
3. 把内容分成三类：会上已定的决定、有负责人的待办、悬而未决的事项。不写会议过程。
4. 做面向某个组的行动卡时，只保留和这个组有关的条目，但会上已定、影响这个组的决定一条都不能漏。每条带上原话作为依据。
5. 原文没写的负责人或截止日不要编，标「待确认」。原文前后矛盾的（比如星期和日期对不上）也标「待确认」，并说明矛盾在哪。
6. 核对日期：星期和日期是否一致，截止日相对今天是否已经过了，有问题就向用户点出来。
7. 交付：文件用 Shell 写到 /workspace/out/ 后作为附件发出；然后用一两句话对照验收标准说明哪些达标、哪些还标着待确认、刻意排除了什么。
8. 不发给任何人，由用户过目后自己转发。
