# 周报流水线

## 什么时候用
用户给出一周的流水账文件，要同时拿到两样东西：交付组能直接用的行动卡，和给用户看的周报。

## 需要什么输入
- 必需：当周流水账文件的路径，例如 `/workspace/项目名/第N周流水账.md`。
- 可选：周次（默认从文件名或正文里取）、每段条数上限（默认 3 条）、输出文件名（默认 `第N周-行动卡.md`、`第N周-周报.md`，放在流水账同一个目录）。
- 缺必需输入，或者看不出是哪一周、哪个项目时，先问用户。

## 步骤
1. **派行动卡**：在项目群里 @行动卡专岗，派活单写清楚：读哪个流水账路径；产出 `第N周-行动卡.md`，列为「事项｜负责人｜截止｜出处（流水账原话）」；只用原文，没写负责人或截止的标「待确认」，不猜；原文件只读不改；做完交回群里。
2. **写周报**：按技能「weekly-report（周报三段式）」写周报，三段是做成了什么、卡住了什么卡在谁、下周做什么带负责人，每段不超过 3 条，最后单独加一行「要我拍板：」。存成 `第N周-周报.md`。只写新文件，不改流水账。
3. **验收**：按下面的清单逐条核对两份文件。不合格的，退回给专岗写明要改哪里，改完再复核一遍。
4. **四段回报**：在群里按「结论／交付物／待决策／下一步」回用户，附上周报文件。

## 怎么验收
- 行动卡：每条都有负责人和截止，或者标了「待确认」；每条都能在流水账里找到原话，出处引的就是原话；没有编造的人名和日期；已经结束的事不列，但要在文末注明。
- 周报：正好三段，每段不超过上限；另有「要我拍板」一行；每条都能对应到原文；②段每条写了卡在谁；③段每条有负责人或「待确认」；不写原文之外的推测。
- 两份文件共同：原文件没被改动；没有发到群外。

## 交回什么
- 群里一条四段回报：
  - 结论：是否通过、一句话概况。
  - 交付物：一张表，写每个文件的验收结果和待确认项。
  - 待决策：最多 3 条，只写需要用户给的人名、日期或拍板。
  - 下一步：用户回复后谁补什么。
- 附上 `第N周-周报.md`，行动卡由专岗在群里发文件。
- 行动卡由用户过目后自己转给交付组，流水线不代发。

## 哪些事先问用户
- 对外发送：发给群外任何人、发邮件、转给交付组。
- 改原文件：流水账一律只读。
- 需要登录任何账号或网站。
- 以上情况都先停下来问，得到明确答复再继续。
